---
name: duplicate-dashboard
description: Duplicate a next-generation Zira dashboard the way Zira web's Duplicate does, in the same site or to another site, where Claude reviews the target site's data sources and metrics and proposes the mapping for the user to confirm. Use for "copy the Band Saw 1 dashboard to South Charleston", "duplicate this dashboard" or "make the same dashboard for Plant 2". Use build-dashboard for a new dashboard and show-dashboards to find existing ones.
---

Use the [local MCP tools](../../references/local-mcp.md) for the packaged commands below. The command examples describe arguments; invoke the corresponding MCP tool instead of running them in a shell.

Read [authorized browsing](../../references/browsing.md) and [guided actions](../../references/actions.md). This follows Zira web's next-generation Duplicate dialog: dashboard → target site → data source and metric mapping → name → copy. The whole flow happens here; do not send the user to Zira's web assistant.

1. **Source.** Reuse the company and site. Find the dashboard with `node ../../scripts/browse.mjs dashboards --company-id ID --site-id ID` and confirm the exact one. Classic dashboards are duplicated in Zira.
2. **Where.** The same site unless the user names another. Resolve another site (or company) through authorized discovery.
3. **Mapping (another site).** Run `node ../../scripts/dashboards.mjs copy-mapping --company-id ID --site-id ID --dashboard-id ID --target-site-id ID [--target-company-id ID] --out FILE --profile prod`. It lists each source data source with the metrics its widgets use, the proposed target data source of the same kind, alternatives, and each metric's match. Targets are chosen one to one: the same unit by name first (type and number, so "Band Saw 1" fits "Bandsaw 1 | Cam 44"), then matching metrics. `widgets` shows what each copied widget gets: its description and its chart's data source. Review it yourself before showing it:
   - Check every proposed data source against the source's name, kind and metrics. Prefer an alternative when it clearly fits better, and say why.
   - `ambiguous` sources fit several targets equally and are left out of `deviceMapping`; `copy` refuses the mapping until each one is chosen. Ask the user, never pick by order.
   - For each unresolved metric, pick from its `candidates` (same unit) when one clearly means the same thing; otherwise leave it and say which widgets may show no data.
   - A data source with no fit maps to null: Zira copies it to the target site.
   - `tileDevices` lists data sources shown by camera and live-count tiles that are not the dashboard's own, with a proposed target by name; confirmed ones go in `mapping.tileDeviceMapping`.
   Show the user a short table (source → target, metrics matched, open questions) and ask them to confirm or change it. Write the confirmed mapping (`deviceMapping`, `metricMapping`, `tileDeviceMapping`) back to FILE.
   In the same site, skip this step: every data source maps to itself.
4. **Preview.** Run `dashboards.mjs copy --company-id ID --site-id ID --dashboard-id ID [--target-site-id ID --target-company-id ID --mapping FILE] [--dashboard-mapping SRC:COPY,…] [--match-site-day-start] [--name "…"] --profile prod`. The default name is `<name> (copy)`; dashboard names are unique per site (Zira answers HTTP 409), so if `nameTaken`, offer `suggestedName`. Say what will be created, what `afterCopy` restores (descriptions and chart data sources that Zira's Duplicate loses), what `relink` fixes after the copy (filter targets, shortcuts, camera/live-count tiles, every breakpoint's layout) and read out `notCopied`. For another site, `siteSettings` compares the two sites' day start and first day of week: these are **site** settings (every dashboard and report there uses them), Zira's Duplicate does not copy them, and `--match-site-day-start` sets the target's to the source's only when the user agrees.
5. **Copy.** After the user confirms, rerun with `--apply`. It copies once, re-saves the widgets whose description or chart data source changed, then relinks: filters target the copy's widgets, shortcuts to the source dashboard open the copy, shortcuts to dashboards in `--dashboard-mapping` open their copies, camera/live-count tiles show the mapped data sources, and the desktop, tablet and phone layouts follow the source (breakpoints the source lacks are derived from desktop, phones stacked full width). Everything is read back. On `created`, give `url` and relay `warnings`: `relink.pendingPlatform` lists saves that wait for Zira's plugin access update (https://github.com/lightapp/platform/pull/248) (shortcut, camera and live-count widgets, list-valued filters); `relink.open` lists links that need a decision (a shortcut to a dashboard with no copy, a tile on an unmapped data source). `orphanedMetrics` lists widgets whose metrics are not on the copy's data sources. Offer schedule-ai-report, since AI reports are not copied.
6. **Several dashboards that link to each other** (a home page with shortcuts to TV and performance pages): copy each one first, then run `dashboards.mjs relink --company-id ID --site-id ID --dashboard-id SOURCE --copy-id COPY --target-site-id ID --mapping FILE --dashboard-mapping SRC1:COPY1,SRC2:COPY2,… --profile prod` for each copy, show its `writes` (exact before/after), and rerun with `--apply --expected REVISION`. `--skip-platform` saves what plugin sign-in can save today and lists the rest as `deferred`; rerun relink once the platform change is deployed. Any further change (names, rotation, a tile's `primaryMetric`, positions) uses `dashboards.mjs edit` (see build-dashboard). Do not click through Zira's web editor for these; report what is still pending instead.
7. **Restore an existing copy.** For a copy made with Zira web's Duplicate, or when `widgetFixes` is incomplete, run `dashboards.mjs fix-copy --company-id ID --site-id ID --dashboard-id SOURCE --copy-id COPY [--target-site-id ID --mapping FILE] --profile prod`. Show its `changes` (only empty descriptions and charts still on the source's data source change) and `skipped`, then rerun with `--apply` after the user approves.
8. **The same section or change on many sites.** When a dashboard that was already copied to several sites gains a section (a header and the widgets below it), do not copy the whole dashboard again. Write a plan for `dashboards.mjs rollout --plan PLAN.json`: `{"version":1,"label":"time-analysis","change":{"copySection":{"source":{companyId,siteId,dashboardId},"header":"Time analysis","position":"bottom"}},"sites":[{companyId,siteId,dashboardId,"deviceMapping":{"SOURCE_ID":"TARGET_ID"}}]}`. Each site's `deviceMapping` maps the source dashboard's data sources to that dashboard's own; a site with more saws or cameras than the source maps one source to a list (`"40":["60","61"]`), which turns "equals" filters into "in" filters. A widget that shows one data source (a readings list, a camera tile) cannot take a list: the preview refuses it by name, so ask the user which one it should show. Review the preview with the user (every dashboard's new widgets, mapped data sources and place), save it, then rerun with `--apply --expected PREVIEW.json --backup-dir DIR`. It refuses a dashboard that already has the section, backs each dashboard up before writing, stops at the first failure and reports `done`, `failed` and `notTried`. `copy`, `fix-copy` and `relink` themselves stay one data source to one.
9. **Remove a copy or leftover widgets.** A copy made by mistake, or an old section a rollout refuses to replace, is removed only on the user's explicit request with `dashboards.mjs delete` (whole dashboard) or `dashboards.mjs delete-widgets` (chosen widgets): show the preview (everything that goes, what points at it, shortcut cards that open the dashboard), get approval of that exact list, then rerun with `--apply --expected REVISION --backup-dir DIR`. A delete cannot be undone; see build-dashboard for the rules. Never delete a source dashboard.

Say "channel", never "system". On `blocked: authorization`, nothing was copied: give `handoff.pageUrl` and its Duplicate instructions. Other stops follow [guided actions](../../references/actions.md).
