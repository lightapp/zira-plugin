---
name: validate-trimsaw-sizes
description: Check whether a Zira trimsaw camera's stop buckets, uncut boards and pre-cut lengths make sense over a chosen window, usually the production since the last calibration, and build an interactive report that explains the charts. Finds relabelled stop lines, explains a high uncut (No Cut) share, checks the camera's scale from uncut boards and shows incoming lengths against the cuts made. Use for "validate Trimsaw 2's sizes after Friday's calibration", "why is uncut 31% on Trimsaw 2", "are the stop lines and pre-cut right" or "explain the trimsaw size charts". Use readings-report for general charts, health-report for device health and show-dashboards for existing Zira dashboards.
---

Read [authorized browsing](../../references/browsing.md) (including "Asking the user to choose"), [reading the report](references/reading-the-report.md) and [handing over local pages](../../references/local-pages.md). Run `node scripts/trimsaw-sizes.mjs …` from this skill's directory with the same `--profile`. It reads Zira through the readings-report cache and writes only to this computer: the cache, a derived copy of the dataset and the HTML report. Nothing is written to Zira or the camera.

**Show, then work.** Share the data source's Zira link as soon as it is known, then fetch.

1. **Data source.** Resolve company and site through authorized discovery, reusing supplied or saved scope. List candidates with `node ../readings-report/scripts/readings.mjs sources --company-id ID --site-id ID --metrics [--search NAME]`. A trimsaw source has Precut Length, Postcut Length, Target Length and No Cut. Ask the user to pick exactly one; when one matches the name they gave, say which one you are using.
2. **Window.** Ask when the stop lines or calibration last changed if the user has not said. Run `windows --company-id ID --site-id ID --device-id ID --from ISO [--to ISO]` over enough days to include that change (default: the last 7 days, with the site's offset). In plain words, show the latest production periods, the change points (`stray-labels-ended`: a calibration session or another device posting; `measured-shift`: a calibration edit or the camera moved; `new-label`: a stop added), the relabels and the `suggested` window with its boards. Ask the user to confirm it, take the whole latest production period or give their own times. Mixing calibrations makes every chart misleading, so keep the window after the last change; a few hundred boards or more is enough.
3. **Check.** Run `check --dataset ID --from LOCAL --to LOCAL` (site time, such as `2026-10-09T10:00`). Say which stops ran and where their cut boards peak, and name each relabel (merged into one stop by default; `--merge none` or explicit pairs like `44=45` override it). Explain the scale check in plain words. When `scale.suggest` is true, ask how to show pre-cut: rescaled by an exact factor the user knows from the camera's calibration (best), by the suggested factor (`auto`, an estimate within about 1%), or as Zira measured it (`none`). Never rescale without asking. If the calibration changed inside the window, use a piecewise factor such as `1.050,1.043@2026-10-09T11:40`.
4. **Report.** Run `report --dataset ID --from LOCAL --to LOCAL --factor none|auto|F [--merge …] --serve`. It writes the derived dataset and the report, starts the readings-report helper and prints `liveUrl`, `savedUrl` and `numbers`. Open `liveUrl` in the host's browser. In chat, give the main points from `numbers`, `scale` and `relabels` only: the uncut split, where each stop peaks, the relabels, the scale decision, the main pre-cut peaks and any long-trim pattern. End with the **Open the report** line from [handing over local pages](../../references/local-pages.md).
5. **Next steps.** Offer what the findings point to, without doing it. A large "longer than stop" uncut share means the saw line sits past the real blade, so thin trims post as No Cut. A relabel means two physical stops shared one line, or the line was renamed. Stops measuring well off their size need recalibration on the camera. This skill does not change camera settings; device setup and line editing happen on the camera or in Zira. Publish a report to share it only when the user asks (for example as a private claude.ai page in Claude Code); it holds customer readings.

To change the window, merges or factor, run `report` again (each run writes a new file). The page's range and interval controls work within the fetched weeks. Its Load button fetches more raw weeks, but those weeks have no derived columns, so build a new report for another window instead.

Limits: one data source per report; readings only, so stop-line pixel positions and camera settings are not visible. The scale check assumes most uncut boards at a stop are already at that size. Pre-cut uses half-unit bins. Tables give per-row medians and percentiles, where a row can hold several boards; the summary numbers and histograms are weighted by boards. Exit codes: 0 done, 2 failed (the message explains), 3 incomplete fetch (say which weeks), 4 blocked (the JSON explains; a sign-in block means the user signs in again).
