---
name: schedule-ai-report
description: Schedule a recurring Zira AI report that reads selected dashboard widgets and emails a written summary to chosen site members. Recurring device health reports use the separate health-report skill and host scheduler.
---

For a recurring device-health check, follow [health-report](../health-report/SKILL.md) and its scheduling reference; retain the selected company/sites, timezone and task policy. Otherwise read [authorized browsing](../../references/browsing.md) and [guided actions](../../references/actions.md). This follows the Home Assistant AI report flow; ask one step at a time and reuse anything already supplied.

1. **Dashboards.** Run `node ../../scripts/ai-report.mjs dashboards --company-id ID --site-id ID --profile prod` and let the user pick up to five. None: offer build-dashboard first.
2. **Schedule.** Offer the presets (`weekdays`, `daily` at 07:00 covering yesterday; `endOfDay` weekdays 17:00 covering that day; `weekly` Monday 07:00 covering last week; `monthly` on the 1st covering last month) or a custom `{"period":"week","days":[0-6],"time":"HH:MM"}` / `{"period":"month","days":[1-31],…}`. Times are the site's local time in Zira. Set `covers` in the schedule (also on a preset) when the user names the data period: `today` (“same day”, “end of day”, “today's data”), `day` (yesterday), `thisWeek`, `week` (last week), `thisMonth`, `month` (last month). Today, this week and this month run up to when the report is sent, so “every day at 18:00 with today's data” is `{"period":"week","days":[0,1,2,3,4,5,6],"time":"18:00","covers":"today"}`. A bare time (“at 5pm”) means every day. Without `covers`, monthly covers last month, one day a week last week, and otherwise yesterday before 12:00 and today from 12:00; state the covered period when you confirm the time, and let the user change either before creating.
3. **Widgets.** Run `ai-report.mjs widgets --company-id ID --site-id ID --dashboard-ids ID,ID` and use all readable widgets unless the user drops some.
4. **Wording.** Offer the focus presets (a period summary; KPI highlights in a table; only problems and exceptions) or the user's own words. Write the standing instruction (`question`): 2–6 plain sentences that say what to cover, which figures to highlight and the layout, referring to widgets by name, without invented targets or numbers. Each run reads only its covered period, so never ask to compare with an earlier period or an average of other weeks; compare within the period or against targets and thresholds the widgets show, and tell the user when a requested comparison is not possible. Write it in English unless the user wants another language, then include “Answer in <language>.” Choose 2–4 `answerStyle` values from: Use Emojis, Use Table, Write Shortly, Use Bullet Points, Include Comparisons, Use Colors, Drill down. Suggest a 2–6 word `name` (the email subject).
5. **Sample (required).** Save the plan JSON to a private temporary file outside the plugin (schema in `ai-report.mjs help`) and run `ai-report.mjs create --plan FILE` (preview only). Using its `sample` block, read the widgets and write the sample in chat exactly as [the sample guide](../../references/ai-report-sample.md) describes, so the user sees what the report will look like. Revise the plan and show a new sample after every change. Nothing may be saved until the user has seen a sample of the current version.
6. **People.** Default recipient is the user (`"me"`). `ai-report.mjs people --company-id ID --site-id ID` lists site members to add.
7. **Save.** Show `confirm` (name, dashboards, when with the covered period, widgets, recipients) and offer two ways, recommending the first when the user wants to check or fine-tune the report in Zira:
   - **Draft and open in Zira:** after a clear yes, run `ai-report.mjs draft --plan FILE --apply`. It creates only the report channel and its AI agent; nothing is scheduled and nobody is emailed. Open `agentUrl` in the host's browser (or give the link): the agent page shows the widgets, instructions and Zira's own sample answer, and the user can edit there. Changes asked for in chat: write a changes JSON (`name`, `question`, `answerStyle`, `widgetIds`, `covers`) and run `update-draft … --changes FILE`, then with `--apply` after a yes, and show a new sample. Before scheduling, run `show` to pick up edits made on the page and, if anything changed, show a new sample. Then run `schedule --plan FILE --channel-id ID --agent-id ID` (plan: companyId, siteId, schedule, recipientIds), show its `confirm`, and after a clear yes rerun with `--apply`. Scheduling uses the agent's current wording, widgets and period. To change the period, use `update-draft` with `covers` first.
   - **Schedule now:** after a clear yes, run `ai-report.mjs create --plan FILE --apply`, which creates the channel, agent, schedule and followers in one step. Each report's followers get it as a post, a notification and an email.

A draft that is not scheduled stays in Zira as a channel with an agent; if the user stops, say it exists and give its channel link so they can finish or delete it. On `drafted`, give `agentUrl` and `channelUrl`. On `created`, give the channel, schedule and agent-editor links and any `warnings`. On `unverified`, the same links plus which parts `verified` could not confirm. On `partial`, list what exists and that it must be finished or removed from those links; do not rerun. A same-name report channel at the site blocks creation (`blocked: duplicate`); pick another name or edit that report in Zira. On `blocked: authorization`, nothing was created: offer the handoff (“Schedule an AI report”) and keep the drafted wording for the step that asks what the report should tell people. Never claim an active schedule without a `created` result.
